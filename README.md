# SAS Fortuna

Custom Frappe app bundling SAS Fortuna's Client Scripts, Server Scripts, Web Forms, Portal Settings, Email Templates, and DocType customizations for version-controlled deployment, built for **Fortuna Impex Pvt Ltd** by **SAS Infosystem Pvt Ltd**.

## Overview

This app packages the customizations built on top of ERPNext v16 for Fortuna Impex Pvt Ltd into a single, installable, version-controlled unit. Instead of customizations living only inside the database (invisible to Git), they're exported as fixtures and shipped as part of this app's source, so they can be reviewed, versioned, and deployed the same way to any ERPNext v16 instance.

## Purpose

- Give SAS Infosystem a repeatable, auditable way to deploy Fortuna Impex's ERPNext customizations.
- Keep customizations in Git instead of only inside one site's database.
- Allow the same customization set to be installed on a fresh ERPNext v16 site (staging, DR, a future client instance) with predictable results.

## Features

| Customization | How it's stored |
|---|---|
| **Custom Fields** | Customize Form additions on standard DocTypes — exported as fixtures, scoped to `CUSTOMIZED_DOCTYPES` in `hooks.py` |
| **Client Scripts** | Form/list-level JavaScript — `sas_fortuna/client_scripts/` (readable mirror) + exported as fixtures (source of truth) |
| **Server Scripts** | Backend automation/validation — `sas_fortuna/server_scripts/` (readable mirror) + exported as fixtures (source of truth) |
| **Web Forms** | Portal-facing forms — exported as fixtures |
| **Email Templates** | Notification templates — exported as fixtures |
| **Portal Settings** | Customer/supplier portal configuration — exported as fixtures (single/settings doctype) |
| **Property Setters** | Field-level property overrides on standard DocTypes — exported as fixtures, scoped to `CUSTOMIZED_DOCTYPES` |
| **Custom DocTypes** | New DocTypes owned by this app, module `SAS Fortuna` — shipped as controller files, **not** fixtures |

The authoritative fixture list, with filters, lives in `sas_fortuna/hooks.py`.

## Requirements

- Frappe Framework v16
- ERPNext v16
- Python and Node versions matching whatever your bench's `bench version` / `node --version` report (this app has no independent version requirement beyond what Frappe v16 itself needs)

## Supported Versions

Built and intended for **Frappe v16 / ERPNext v16** only. No effort has been made to support v13–v15; if you need that, treat this as a starting point and re-verify every fixture DocType name and hook against that version's `bench` output.

```
    ├── templates/pages/           # portal/website pages, if any
    ├── www/                       # website routes, if any
    ├── sas_fortuna/                # the "SAS Fortuna" module — new Custom DocTypes live here
    │   └── doctype/

    ├── server_scripts/            # readable mirror of exported Server Script fixtures
    └── fixtures/                  # generated by `bench export-fixtures` — the deployed source of truth
```

**Deliberately not present: `config/desktop.py`.** That module was Frappe's pre-v13 mechanism for desk module icons and is not read by v16 — using it would be dead code. Module visibility in current Frappe is handled by **Workspace** records instead; if SAS Fortuna needs a dedicated workspace, add one via the Desk UI and fixture-export the `Workspace` doctype the same way as everything else above, rather than reviving `desktop.py`.

## Development Setup

This app's source was prepared outside of a live bench (see `INSTALL_INSTRUCTIONS.md` for why and exactly how to merge it in). Once merged into a real bench:

```bash
cd frappe-bench
bench get-app sas_fortuna ./apps/sas_fortuna   # if merging locally, or bench get-app <repo-url>
bench --site <site-name> install-app sas_fortuna
bench --site <site-name> migrate
bench build --app sas_fortuna
```

## Installation

### On a bench with the app already present (dev)

```bash
bench --site [site-name] install-app sas_fortuna
bench --site [site-name] migrate
```

### On a new bench (client deployment)

```bash
bench get-app https://github.com/subhapriyo/SAS_FORTUNA.git
bench --site [client-site-name] install-app sas_fortuna
bench --site [client-site-name] migrate
```

`bench migrate` syncs any custom DocType schema and imports all fixtures (Custom Fields, Client/Server Scripts, Web Forms, Email Templates, Portal Settings, Property Setters).

### Installing on a Site — logo/branding step

The logo ships as a static asset at `/assets/sas_fortuna/images/logo.png` after `bench build`, but Frappe v16 has no hook that auto-applies an app logo to the UI. To actually show it, set it explicitly per site: **Website Settings > App Logo / Banner Image**, pointing at the asset path above. Do this once per site after install; it is not fixture-exported (it's a Website Settings field on a singleton doctype tied to the site's own branding, not an app-owned customization).

## Fixture Management

Fixtures are scoped, never a blind full-table export. See `sas_fortuna/hooks.py` for the exact filters. In short:

- **Custom Field / Property Setter** — filtered to the DocTypes listed in `CUSTOMIZED_DOCTYPES` in `hooks.py`. Add a DocType there *before* you customize it, or the export will silently skip your change.
- **Client Script / Server Script / Web Form / Email Template** — filtered by an explicit, hand-maintained list of exact record names in `hooks.py` (`CUSTOM_CLIENT_SCRIPTS`, `CUSTOM_SERVER_SCRIPTS`, `CUSTOM_WEB_FORMS`, `CUSTOM_EMAIL_TEMPLATES`). Add a record's exact name to the matching list the moment you create it — an unlisted record is skipped on export, not swept in. If you rename a record, update the list entry too.
- **Portal Settings** — a per-site singleton, exported without a filter (nothing unrelated to pull in).

Never remove the filters to "just export everything" — that's how unrelated site data, or another app's customizations, ends up committed to this repo.

## Exporting Customizations

Whenever customizations are added or changed via Customize Form, Client Script, Server Script, Web Form, Email Template, or Portal Settings in the Desk UI, re-export before committing:

```bash
bench --site [dev-site-name] export-fixtures --app sas_fortuna
```

Then:

```bash
git diff sas_fortuna/fixtures/
```

Review this diff line by line before committing. Confirm every changed/added record actually belongs to SAS Fortuna, contains no site-specific IDs (company, warehouse, user), and contains no secrets.

## Frappe Cloud Deployment

```
Developer machine → Frappe Bench → sas_fortuna app → Git → GitHub → Frappe Cloud → Private Bench → ERPNext Site
```

Frappe Cloud only installs custom apps on a **Private Bench** you control (not the shared/public managed benches). To deploy:

1. Connect the GitHub account/organization to Frappe Cloud (Frappe Cloud dashboard > your team > GitHub settings) — this grants Frappe Cloud read access to the repo; making the repo public/private alone does **not** grant access.
2. In your Private Bench, add `sas_fortuna` as a custom app, pointing at `https://github.com/subhapriyo/SAS_FORTUNA.git` and the branch to track (`main`).
3. Deploy the bench (Frappe Cloud builds and deploys the app onto that bench).
4. Install the app on the target site from the Frappe Cloud site dashboard, or via `bench --site <site> install-app sas_fortuna` if you have console access.
5. Run any pending migration from the site dashboard (or `bench --site <site> migrate`).
6. Verify: app in Installed Apps, Custom DocTypes present, fixtures imported, logo asset loads, no migration errors.

## Updating the App

```
Developer → edit code / export fixtures → Git commit → GitHub push → Frappe Cloud pull/deploy → Bench update → Site migration → Updated SAS Fortuna
```

For fixture-based changes specifically:

```bash
bench --site <site> export-fixtures --app sas_fortuna
git diff sas_fortuna/fixtures/     # review — never blindly commit a full export
git add sas_fortuna/fixtures/
git commit -m "fix: <what changed>"
git push
```

Then deploy via Frappe Cloud as above.

## Rollback Strategy

- **Code rollback:** `git revert` the offending commit(s) on `main`, redeploy through Frappe Cloud.
- **Deployment rollback:** Frappe Cloud keeps prior deploys; redeploy a previous successful build if the new one is bad.
- **Migration considerations:** `bench migrate` is not guaranteed to be reversible. A schema change that ran forward (e.g. a new mandatory field with data backfilled) may require a *new forward migration* to undo, not a blind rollback. Treat any migration touching existing data as one-way until proven otherwise on a test site.
- **Fixture rollback:** reverting the Git commit that changed a fixture and re-running `bench migrate` will re-import the old fixture state — but this does not delete records that a *newer* fixture created and an *older* one didn't have; check manually.

## Troubleshooting

- **Fixture didn't import:** confirm the record's name/doctype actually matches the filter in `hooks.py`, then re-run `bench migrate`.
- **Custom Field not appearing after install:** run `bench --site <site> migrate` again and `bench --site <site> clear-cache`.
- **Logo not showing:** confirm `bench build --app sas_fortuna` ran, then check Website Settings > App Logo is actually pointed at `/assets/sas_fortuna/images/logo.png` (see Installation, above) — this step is per-site and not automatic.
- **`bench export-fixtures` pulled in unrelated records:** your filter in `hooks.py` is too broad, or a record on the site doesn't follow the naming/DocType convention this app relies on. Fix the filter or rename the record; don't hand-edit the exported JSON to hide the problem.

## Security

- No passwords, API keys, tokens, or credentials are stored in this repository. If a Server Script or Client Script ever needs a secret, use `frappe.conf` / site config on the target site, never hard-code it.
- `sites/`, `site_config.json`, and any local dev artifacts are gitignored — verify with `git status` before every commit.
- Review every fixture JSON diff before committing (see Exporting Customizations) — the biggest realistic leak risk here is an over-broad fixture export, not application code.

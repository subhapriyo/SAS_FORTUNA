# How to use this package

## Why this isn't a raw `bench new-app` output

This was prepared in a sandbox with no Frappe bench, no `bench` CLI, and
no outbound network access (verified: `bench` not installed, no
`frappe-bench` directory anywhere, and `curl https://github.com` returned
`403 host_not_allowed`). That means I could not actually run
`bench new-app sas_fortuna` and hand you its real, version-exact output
for files like `pyproject.toml`, `license.txt`, and `MANIFEST.in` — those
are generated by Frappe's own cookiecutter template and can shift
slightly between patch releases. Rather than fabricate those and risk
handing you something subtly wrong, this package is an **overlay**: the
custom, hand-written parts (hooks, fixtures config, README, pre-commit,
logo, script folders) that you merge on top of the real scaffold your own
bench generates.

## Steps

1. On your actual bench:

   ```bash
   cd frappe-bench
   bench new-app sas_fortuna
   ```

   Answer the prompts with:
   - App Title: `SAS Fortuna`
   - App Description: `Custom Frappe app bundling SAS Fortuna's Client Scripts, Server Scripts, Web Forms, Portal Settings, Email Templates, and DocType customizations for version-controlled deployment.`
   - App Publisher: `SAS Infosystem Pvt Ltd`
   - App Email: `subhapriyo@gmail.com`
   - App License: `mit`

2. Confirm it worked:

   ```bash
   bench --site <your-site> list-apps
   ls apps/sas_fortuna
   ```

3. Copy this overlay on top, **without deleting** the scaffold's own
   `pyproject.toml`, `license.txt`, `MANIFEST.in`, or the auto-generated
   `sas_fortuna/__init__.py` (it holds `__version__` — keep it):

   ```bash
   # from wherever you extracted this package
   cp -r sas_fortuna/hooks.py            frappe-bench/apps/sas_fortuna/sas_fortuna/hooks.py
   cp -r sas_fortuna/modules.txt         frappe-bench/apps/sas_fortuna/sas_fortuna/modules.txt
   cp -r sas_fortuna/patches.txt         frappe-bench/apps/sas_fortuna/sas_fortuna/patches.txt
   cp -r sas_fortuna/public/images       frappe-bench/apps/sas_fortuna/sas_fortuna/public/
   cp -r sas_fortuna/client_scripts      frappe-bench/apps/sas_fortuna/sas_fortuna/
   cp -r sas_fortuna/server_scripts      frappe-bench/apps/sas_fortuna/sas_fortuna/
   cp -r sas_fortuna/fixtures            frappe-bench/apps/sas_fortuna/sas_fortuna/
   cp -r sas_fortuna/templates           frappe-bench/apps/sas_fortuna/sas_fortuna/
   cp -r sas_fortuna/sas_fortuna         frappe-bench/apps/sas_fortuna/sas_fortuna/   # the module package (doctype/ home)
   cp README.md                          frappe-bench/apps/sas_fortuna/README.md
   cp .pre-commit-config.yaml            frappe-bench/apps/sas_fortuna/
   cp .gitignore                         frappe-bench/apps/sas_fortuna/.gitignore   # merge, don't blindly overwrite if new-app already made one
   ```

   Then diff the generated `hooks.py` against the one you're copying in —
   `bench new-app` may have left commented boilerplate you want to keep
   or intentionally drop; don't overwrite blind (see project Rule 3).

4. Install and verify:

   ```bash
   bench --site <site> install-app sas_fortuna
   bench --site <site> migrate
   bench build --app sas_fortuna
   bench --site <site> run-tests --app sas_fortuna
   ```

5. Pre-commit:

   ```bash
   cd apps/sas_fortuna
   pre-commit install
   pre-commit run --all-files
   ```

   Fix anything it flags rather than skipping with `--no-verify`.

6. Git:

   ```bash
   cd apps/sas_fortuna
   git status
   git diff
   git add -A
   git commit -m "feat: initialize SAS Fortuna ERPNext v16 custom app"
   git remote add origin https://github.com/subhapriyo/SAS_FORTUNA.git
   git push -u origin main
   ```

   Before the push: re-check `git diff --stat` and grep for anything that
   looks like a secret. Do not push if unsure — ask first.

7. Report back the *actual* output of `bench version`, `list-apps`, and
   `run-tests` here so fixture DocType names and hooks can be
   double-checked against your real Frappe v16 patch version rather than
   left as reasonable-but-unverified assumptions.
